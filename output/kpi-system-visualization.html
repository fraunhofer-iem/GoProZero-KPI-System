The big picture

From five domains to one score

At the very top sits one number. It is built from five domains, each of which breaks down into sub-scores, and those into deeper scores, until you reach the raw data points someone must supply.

Sustainability
composite of the five domains
The domains are not fully separate. A few raw inputs feed parents in more than one domain, so the structure is really a network, not five isolated trees — the same measurement can legitimately matter to several aspects of sustainability.

Structure

Five levels, colour-coded

Every indicator sits at one of five levels. Higher-level scores are darker green; the Level-5 raw data points are grey — those are the ones you supply numbers for.

The ID scheme

Each domain has a letter prefix. EN0 is the domain score; EN1, EN2… are Level-2 sub-scores; add a digit per level down (EN11, EN131); raw data points are written with a hyphen (EN1-1). The ID itself encodes the tree.

⚠ A naming collision to watch for

In Resource Efficiency the IDs R0–R9 look identical to the circular-economy R-principles R0–R9 (R2 = Reduce) in the glossary. They are completely different things. Always read R2 by context.

How it computes

Read top-down, calculate bottom-up

You read the tree top-down to understand it, but numbers flow upward. You supply the Level-5 raw data points; each score combines its children, feeds its parent, and so on up to the domain score and finally the composite.

The engine

Calculation strategies

Every row's Calculation Strategy says how its value is produced. Leaves are raw values; above them a row is either a score (always 0–1) or a raw total (a sum or formula in kg, €, …). The number on each card is how many indicators use that strategy.

Per-company settings

Weights & normalization

Weights sum to 1

When a score combines several children, a weight says how much each child counts. Under any one parent, the weights of all direct children should add up to 1, keeping every score on the same 0–1 scale. The template ships equal 1/N defaults; each company overrides them. If a whole branch has no data, its weight is effectively treated as 0 so it drops out rather than dragging the score down.

1 = good, 0 = bad everywhere. Scores are shown as a percentage of that 0–1 fraction.

Normalization & direction

Raw values are mapped to 0–1 by min-max normalization: (Value − Min) / (Max − Min). There is no separate higher/lower switch — direction is decided entirely by which bound is larger.

Higher is better

shares, ratings, efficiency
Min = worstMax = best
Min < Max (ascending band)

Lower is better

intensity, time, cost
Min = worstMax = best
Invert: set Min > Max
Mind the direction. For e.g. energy-per-unit where 25 kWh is worst and 0 is ideal, set Min = 25, Max = 0. A 5 kWh product then scores 0.8. An ordinary ascending band would score it backwards.
For practitioners

The recommended workflow

The key sequence: understand top-down → gather data first → set weights and min/max afterwards.

  1. Read the Overview & Top-Level sheets.Orient yourself: the goal, the structure, the R-principles, and what each of the five domains means.
  2. Pick a domain and drill down, top-down.Read from the Level-1 score down to the Level-5 raw data points to see why each input is needed and where it fits.
  3. Identify the raw inputs you must supply.They are the grey Data? = x rows. The Metrics List sheet is the flat checklist of all of them, with links back to context.
  4. Gather the data first.Use each row's Unit, Data Source (often LCA) and Life-Cycle Stages to know what to measure — before worrying about weights.
  5. Then set the per-company values.Fill in Weights (sum to 1 under each parent) and the Target Min / Target Max reference values. Mind the direction for lower-is-better metrics.
  6. Consult the References as needed.For any KPI whose basis you want to verify, follow its Reference code to the References sheet.
